## ส่วนที่ 1: ขั้นตอนก่อนร่าง TOR (ข้อกำหนดเบื้องต้นจากหน่วยงาน)

### 1.1 สิ่งที่หน่วยงานต้องเตรียมมาก่อน (Requirements)

ก่อนที่จะเริ่มร่าง TOR ได้ หน่วยงานภาครัฐ (ผู้ว่าจ้าง) ต้องจัดเตรียมข้อมูลดังนี้:

| ลำดับ | ข้อมูลที่ต้องเตรียม | รายละเอียด | ผู้รับผิดชอบ |
|-------|---------------------|-----------|-------------|
| ๑ | หนังสืออนุมัติโครงการ | ได้รับอนุมัติจากผู้มีอำนาจแล้ว | ผู้บริหาร |
| ๒ | แผนจัดซื้อจัดจ้างประจำปี | ลงประกาศในระบบ e-GP แล้ว | เจ้าหน้าที่พัสดุ |
| ๓ | ความต้องการ (Requirements) | ระบุปัญหา เป้าหมาย ขอบเขตคร่าวๆ | หน่วยงานผู้ใช้ |
| ๔ | งบประมาณที่ได้รับจัดสรร | วงเงินที่ใช้ได้จริง | การเงิน |
| ๕ | คำสั่งแต่งตั้งคณะกรรมการ | กรรมการจัดทำ TOR ≥3 คน | ผู้บังคับบัญชา |
| ๖ | ข้อมูลระบบเดิม (ถ้ามี) | รายการอุปกรณ์/ระบบ S/N ยี่ห้อ รุ่น | ฝ่าย IT |
| ๗ | นโยบาย/แผนยุทธศาสตร์ที่อ้างอิง | แผนดิจิทัล แผนปฏิบัติราชการ | ฝ่ายแผน |

### 1.2 ขั้นตอนการดำเนินการก่อนร่าง TOR

```
┌─────────────────────────────────────────────────────┐
│ ขั้นตอนที่ ๑: หน่วยงานผู้ใช้ระบุความต้องการ         │
│ (เอกสาร: บันทึกข้อความขอจัดซื้อจัดจ้าง)             │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ ขั้นตอนที่ ๒: ผู้บริหารอนุมัติหลักการ               │
│ (ตรวจสอบว่าอยู่ในแผนจัดซื้อจัดจ้าง + มีงบ)         │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ ขั้นตอนที่ ๓: แต่งตั้งคณะกรรมการจัดทำ TOR           │
│ (≥3 คน มีผู้เชี่ยวชาญด้านเทคนิค)                   │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ ขั้นตอนที่ ๔: สืบราคา/ประเมินราคากลาง              │
│ (ใช้แหล่งข้อมูลตามหัวข้อถัดไป)                      │
└────────────────────┬────────────────────────────────┘
                     ▼
┌─────────────────────────────────────────────────────┐
│ ขั้นตอนที่ ๕: ร่าง TOR                              │
│ (ใช้โครงสร้างตามประเภทงาน ดูส่วนที่ 3)              │
└─────────────────────────────────────────────────────┘
```

**สำคัญ:** หากหน่วยงานยังไม่ได้เตรียมข้อมูลข้างต้นครบ ให้ถามก่อนทุกครั้ง ห้ามสมมติเอง

        ↓ (ถ้าไม่มี)

```

### 2.4 วิธีคำนวณราคากลางงาน IT (ตัวอย่างจริง)

**ก. งานพัฒนาระบบ (Man-day Rate):**
| ตำแหน่ง | อัตรา (บาท/วัน) | ที่มา |
|---------|----------------|-------|
| หัวหน้าโครงการ | 12,000 - 20,000 | สืบราคาตลาด/สบน. |
| นักวิเคราะห์ระบบอาวุโส | 8,000 - 12,000 | สืบราคาตลาด |
| นักพัฒนาระบบ | 5,000 - 8,000 | สืบราคาตลาด |
| ผู้ทดสอบระบบ | 4,000 - 6,000 | สืบราคาตลาด |
| ผู้ดูแลฐานข้อมูล | 6,000 - 10,000 | สืบราคาตลาด |

**สูตร:** ราคากลาง = Σ(จำนวนคน × จำนวนวันทำงาน × อัตรารายวัน) + ค่า License + ค่า Infrastructure + ค่าดำเนินการ (15-20%)

**ข. งานบำรุงรักษา (MA):**
- สืบราคาจากผู้ให้บริการ ≥3 ราย
- เทียบกับราคาสัญญาเดิม (ถ้ามี)
- คำนึงถึงอุปกรณ์ที่หมดประกัน (Out of Warranty)
- รวมค่าอะไหล่/วัสดุสิ้นเปลือง (แบตเตอรี่ Filter น้ำมัน)

**ค. งาน Cloud/SaaS:**
- ใช้ราคา Published Rate จากผู้ให้บริการ (AWS/Azure/GCP)
- คำนวณ: จำนวนทรัพยากร × ระยะเวลา × อัตราค่าบริการ
- เปรียบเทียบแบบ On-Demand vs Reserved Instance
- รวมค่า Support/Managed Service (15-25%)

## ส่วนที่ 3: โครงสร้าง TOR มาตรฐาน (ตรงตามตัวอย่างจริง)

### 3.1 โครงสร้างสำหรับงานจ้างบำรุงรักษา IT (ตามแบบ TOR 506, 513)

```
ร่างขอบเขตของงาน (Terms of Reference: TOR)
โครงการ [ชื่อโครงการ]
[ชื่อหน่วยงาน]

๑. ความเป็นมา / หลักการและเหตุผล
   (อธิบายภารกิจหน่วยงาน → ระบบที่มีอยู่ → เหตุผลที่ต้องบำรุงรักษา)

๒. วัตถุประสงค์
   ๒.๑ เพื่อ...
   ๒.๒ เพื่อ...

๓. เกณฑ์การพิจารณา
   (ราคาต่ำสุด — สำหรับงาน MA ที่ขอบเขตชัดเจน)

๔. คุณสมบัติของผู้ยื่นข้อเสนอ
   ๔.๑ - ๔.๙  คุณสมบัติมาตรฐาน 9 ข้อ (ม.64-66)
   ๔.๑๐ กิจการร่วมค้า (ถ้าอนุญาต)
   ๔.๑๑ ลงทะเบียน e-GP
   ๔.๑๒ มูลค่าสุทธิกิจการ (ตามตาราง 9 ระดับ)
   ๔.๑๓ ผลงาน (ระบุประเภท + วงเงินขั้นต่ำ + ย้อนหลังกี่ปี)
   ๔.๑๔ ตัวแทนจำหน่าย/ให้บริการ (หนังสือรับรองจากผู้ผลิต)

๕. เงื่อนไขการเสนอราคา
   (ตารางเปรียบเทียบคุณสมบัติ — Statement of Compliance)

๖. ขอบเขตของงาน
   ๖.๑ การบำรุงรักษาเชิงป้องกัน (Preventive Maintenance)
       - รายการตรวจสอบ (Checklist) แต่ละระบบ
       - ความถี่ (อย่างน้อย 4 ครั้ง/ปี)
   ๖.๒ การบำรุงรักษาเชิงแก้ไข (Corrective Maintenance)
       - เวลาตอบรับ (ไม่เกิน 4 ชั่วโมง)
       - เวลาแก้ไข (ไม่เกิน 24 ชั่วโมง)
       - อุปกรณ์ทดแทน (กรณีซ่อมไม่ได้)
   ๖.๓ ตารางรายการอุปกรณ์/ระบบ (พร้อม S/N)

๗. ระยะเวลาดำเนินงาน
   (ระบุจำนวนวัน "นับถัดจากวันลงนามในสัญญา")

๘. วงเงินงบประมาณ
   "เป็นจำนวนเงินทั้งสิ้น X บาท (ตัวอักษร) 
    รวมภาษีมูลค่าเพิ่มและค่าใช้จ่ายทั้งปวงแล้ว"

๙. เงื่อนไขการส่งมอบงาน
   (แบ่งเป็นงวด พร้อมระบุ Deliverables แต่ละงวด)

๑๐. การเบิกจ่ายเงิน
   (สัดส่วนแต่ละงวด รวมกัน = 100%)

๑๑. เงื่อนไขค่าปรับ
   "ชำระค่าปรับเป็นรายวัน ในอัตราร้อยละ 0.10 ของมูลค่า..."

๑๒. ข้อสงวนสิทธิ์

๑๓. หน่วยงานผู้รับผิดชอบ
   (ที่อยู่ + โทรศัพท์ + อีเมล สำหรับสอบถาม/วิจารณ์)

ภาคผนวก ก: รายการอุปกรณ์ (ตารางละเอียด)
ภาคผนวก ข: รายละเอียดการบำรุงรักษา (Checklist)
```

### 3.2 โครงสร้างสำหรับงานจ้างพัฒนาระบบ IT (ตามแบบ TOR 514)

```
ขอบเขตของงาน (Terms of Reference: TOR) และราคากลาง
จ้างพัฒนา [ชื่อระบบ]
[ชื่อหน่วยงาน]

๑. ความเป็นมา
   (สภาพปัจจุบัน → ปัญหา → แนวทางแก้ → ความจำเป็น)

๒. วัตถุประสงค์
   ๒.๑ - ๒.๖ (เขียนให้วัดผลได้)

๓. คุณสมบัติของผู้รับจ้าง
   ๓.๑ - ๓.๑๑ คุณสมบัติมาตรฐาน + e-GP + มูลค่าสุทธิ
   ๓.๑๒ ขึ้นทะเบียนที่ปรึกษา (ศูนย์ข้อมูลที่ปรึกษา กระทรวงการคลัง)
   ๓.๑๓ ผลงานประเภทเดียวกัน
   ๓.๑๔ บุคลากรที่ต้องการ
        (๑) บุคลากรหลัก — ตาราง (ตำแหน่ง/ประสบการณ์/วุฒิ/จำนวน/ระยะเวลา)
        (๒) บุคลากรสนับสนุน — ตาราง

๔. ขอบเขตของงาน
   ๔.๑ งานสำรวจและรวบรวมความต้องการ
   ๔.๒ งานวิเคราะห์และออกแบบระบบ
   ๔.๓ งานพัฒนาระบบ (ระบุ Module/ฟังก์ชัน)
   ๔.๔ งานทดสอบระบบ (SIT + UAT)
   ๔.๕ งานติดตั้งระบบ
   ๔.๖ งานฝึกอบรม
   ๔.๗ งานจัดทำเอกสาร

๕. ข้อกำหนดทางเทคนิค
   ๕.๑ สถาปัตยกรรมระบบ
   ๕.๒ ความปลอดภัย (PDPA, Encryption, Audit Log)
   ๕.๓ ประสิทธิภาพ (Response Time, Concurrent Users)
   ๕.๔ การเชื่อมต่อระบบอื่น (API/Integration)

๖. เกณฑ์การพิจารณาคัดเลือก
   (Price Performance — เทคนิค:ราคา เช่น 50:50 หรือ 60:40)

๗. เอกสารที่ต้องส่งมอบ
   (SRS, SDS, Source Code, คู่มือผู้ใช้, คู่มือผู้ดูแล, รายงานทดสอบ)

๘. วงเงินงบประมาณ
   "เป็นจำนวนเงินทั้งสิ้น X บาท (ตัวอักษร)
    รวมภาษีมูลค่าเพิ่มและค่าใช้จ่ายทั้งปวงแล้ว"

๙. กำหนดเวลาส่งมอบงาน
   "ภายในระยะเวลา X วัน นับถัดจากวันลงนามในสัญญา"

๑๐. งวดงานและการชำระเงิน
   งวดที่ ๑: ร้อยละ 20 — วิเคราะห์/ออกแบบ
   งวดที่ ๒: ร้อยละ 60 — พัฒนา/ทดสอบ/ติดตั้ง
   งวดที่ ๓: ร้อยละ 20 — ฝึกอบรม/คู่มือ/ส่งมอบสุดท้าย

๑๑. เงินประกันผลงาน
   "หักร้อยละ 10 ของค่าจ้างแต่ละงวด คืนพร้อมงวดสุดท้าย"

๑๒. อัตราค่าปรับ
   "ร้อยละ 0.10 ต่อวัน ของราคางวดงานที่ล่าช้า"
   "ค่าปรับ SLA ช่วงรับประกัน: ร้อยละ 0.035 ต่อชั่วโมงที่เกินกำหนด"

๑๓. การรับประกัน
   "ไม่น้อยกว่า 2 ปี นับถัดจากวันตรวจรับงวดสุดท้าย"
   (ระบุเงื่อนไข: PM ทุกเดือน, แก้ไข Bug ภายใน X ชม.)

๑๔. ลิขสิทธิ์และทรัพย์สินทางปัญญา
   "Source Code และทรัพย์สินทางปัญญาทั้งหมดเป็นของ [หน่วยงาน]"
