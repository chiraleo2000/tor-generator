## 2. โครงสร้างหัวข้อที่พบ (Section Structure Patterns)

### 2.1 รูปแบบการเรียงหัวข้อ

| หัวข้อ | 506 (MA IT) | 513 (MA DC) | 514 (Dev+Consult) |

### 2.2 ข้อสังเกตเรื่องโครงสร้าง
- **การเรียงเลข:** ใช้เลขไทย (๑, ๒, ๓...) ทั้ง 3 ฉบับ
- **ข้อย่อย:** ใช้จุดทศนิยม (๕.๑.๑, ๕.๑.๒) ทุกฉบับ
- **รายการย่อย:** ใช้วงเล็บเลขไทย (๑), (๒), (๓) สำหรับคุณสมบัติตามกฎหมาย
- **งาน MA:** เน้น PM/CM, SLA, ตารางอุปกรณ์
- **งาน Dev:** เน้น บุคลากร, Deliverables, ระบบที่พัฒนา, รับประกัน, ลิขสิทธิ์

## 3. รูปแบบคุณสมบัติผู้ยื่นข้อเสนอ (Qualification Patterns)

### 3.1 คุณสมบัติมาตรฐาน 9 ข้อ (พบในทั้ง 3 ฉบับ)
1. มีความสามารถตามกฎหมาย
2. ไม่เป็นบุคคลล้มละลาย
3. ไม่อยู่ระหว่างเลิกกิจการ
4. ไม่ถูกระงับการยื่นข้อเสนอ (ไม่ผ่านเกณฑ์ประเมิน)
5. ไม่เป็นผู้ทิ้งงาน
6. มีคุณสมบัติตามคณะกรรมการนโยบายฯ กำหนด
7. เป็นผู้มีอาชีพรับจ้างงาน
8. ไม่มีผลประโยชน์ร่วมกัน / ไม่ขัดขวางการแข่งขัน
9. ไม่ได้รับเอกสิทธิ์คุ้มกัน

### 3.2 คุณสมบัติเพิ่มเติมที่พบ

| คุณสมบัติเพิ่มเติม | 506 | 513 | 514 |
|---------------------|-----|-----|-----|
| กิจการร่วมค้า (JV rules) | ✓ ละเอียดมาก | ✓ อ้างเอกสาร | ✓ ละเอียด |
| ลงทะเบียน e-GP | ✓ | ✓ | ✓ |
| มูลค่าสุทธิกิจการ (9 ระดับ) | ✓ ตารางเต็ม | ✓ อ้างเอกสาร | ✓ ระบุ 3 ล้าน |
| นิติบุคคล ≥5 ปี | ✓ | - | - |
| ผลงานขั้นต่ำ | ≥30 ล้าน (Web/MA) | ≥2.5 ล้าน (DC/IT) | ≥1 ล้าน (IT Dev) |
| ตัวแทนจำหน่าย/ผู้ผลิต | - | ✓ (UPS/AC/Gen) | - |
| ขึ้นทะเบียนที่ปรึกษา | - | - | ✓ (ICT ระดับ 1) |
| Certification บุคลากร | ✓ (A+, CCNA, UNIX) | - | - |
| บุคลากรละเอียด | - | - | ✓ (หลัก 7 + สนับสนุน 8) |

### 3.3 ตารางมูลค่าสุทธิกิจการ (จาก TOR 506)

| ระดับ | วงเงินจัดซื้อจัดจ้าง | ทุนจดทะเบียนขั้นต่ำ |
|-------|----------------------|---------------------|
| (๑) | ไม่เกิน 1 ล้าน | ไม่กำหนด |
| (๒) | >1 ล้าน - 5 ล้าน | 1 ล้าน |
| (๓) | >5 ล้าน - 10 ล้าน | 2 ล้าน |
| (๔) | >10 ล้าน - 20 ล้าน | 3 ล้าน |
| (๕) | >20 ล้าน - 50 ล้าน | 5 ล้าน |
| (๖) | >50 ล้าน - 150 ล้าน | 20 ล้าน |
| (๗) | >150 ล้าน - 300 ล้าน | 50 ล้าน |
| (๘) | >300 ล้าน - 500 ล้าน | 100 ล้าน |
| (๙) | >500 ล้าน | 200 ล้าน |

**หมายเหตุ:** บุคคลธรรมดาต้องมีเงินฝาก 1/5 ของวงเงินโครงการ (ไม่เกิน 50 วันก่อนยื่น)

## 4. รูปแบบ SLA และการบำรุงรักษา (Maintenance Patterns)

### 4.1 Preventive Maintenance (PM)
| รายการ | 506 | 513 |
|--------|-----|-----|
| ความถี่ | ทุกเดือน | อย่างน้อย 4 ครั้ง/ปี |
| ขอบเขต | HW + SW ทั้งหมด | Data Center + ระบบ IT |
| รายงาน | - | รายงานทุกงวด |

### 4.2 Corrective Maintenance (CM)
| รายการ | 506 | 513 | 514 (warranty) |
|--------|-----|-----|----------------|
| Response time | - | 4 ชม. | 1 ชม. |
| Resolution time | 4 ชม. | 24 ชม. | 4 ชม. |
| นับรวมวันหยุด | - | ✓ | - |
| อุปกรณ์ทดแทน | ✓ (30 วัน) | ✓ | - |
| ค่าปรับ SLA | - | - | 0.035%/ชม. |

### 4.3 ข้อกำหนด SLA ที่พบ
- **ช่างเทคนิค:** ต้องมี Certification (TOR 506: A+, CCNA, UNIX)
- **Single Point of Contact:** จุดรับแจ้งปัญหาจุดเดียว (TOR 506)
- **อุปกรณ์สำรอง:** ต้องนำมาติดตั้งทดแทนทันที
- **การคืนอุปกรณ์:** ซ่อมเสร็จ 30 วัน หรือจัดหาใหม่ 15 วัน

## 5. รูปแบบค่าปรับ (Penalty Patterns)

| TOR | อัตราค่าปรับ | ฐานคำนวณ | เงื่อนไขพิเศษ |
|-----|-------------|----------|---------------|
| 506 | (ไม่ปรากฏในส่วนที่อ่านได้) | - | - |
| 513 | 0.10%/วัน | มูลค่าในสัญญา | ส่งมอบแล้วแต่ใช้งานไม่ได้ |
| 514 | 0.10%/วัน | ราคางวดนั้นๆ | +0.035%/ชม. สำหรับ SLA (warranty) |

**ข้อสังเกต:**
- อัตรา 0.10%/วัน เป็นอัตราที่พบบ่อยที่สุดในงาน IT/MA
- TOR 514 มีค่าปรับ 2 ชั้น: ปรับส่งมอบช้า + ปรับ SLA ระหว่างรับประกัน
- TOR 513 ใช้ฐานคำนวณจากมูลค่าสัญญาทั้งหมด (ไม่แยกงวด)

## 8. เกณฑ์การพิจารณา (Evaluation Criteria Patterns)

## 9. ข้อกำหนดเฉพาะตามประเภทงาน

### 9.1 งาน IT MA (TOR 506, 513)
- ตารางรายการอุปกรณ์พร้อม Serial Number
- แยก Site (หลัก + DR)
- ระบุยี่ห้อ/รุ่นอุปกรณ์ที่ต้องดูแล (มีเหตุผลเพราะเป็นอุปกรณ์เดิม)
- Statement of Compliance (ตารางเปรียบเทียบ spec)
- Certification ช่างเทคนิค
- Single Point of Contact

### 9.2 งาน Development + Consulting (TOR 514)
- ขึ้นทะเบียนที่ปรึกษา (ศูนย์ข้อมูลที่ปรึกษา กระทรวงการคลัง)
- บุคลากรละเอียดมาก (ตาราง + คุณสมบัติแต่ละตำแหน่ง)
- Deliverables เอกสารมากมาย (SRS, SDS, Data Dictionary, คู่มือ)
- ส่งมอบ Source Code + ลิขสิทธิ์เป็นของหน่วยงาน
- รับประกัน 2 ปี (รวม PM ทุกเดือน)
- Cloud Server จัดหาในโครงการ
- Presentation ต่อคณะกรรมการ (1 ชม. + Q&A 10 นาที)
- Line OA Integration
- PDPA compliance

### 9.3 งาน Data Center MA (TOR 513)
- แยกระบบชัดเจน: UPS, CRAC, Generator, Access Control, CCTV, Fire Alarm
- ตัวแทนจำหน่าย/บริการ ต้องมีหนังสือรับรองจากผู้ผลิต
- Appendix แยกรายการอุปกรณ์ (ภาคผนวก ก, ข)
- PM checklist ละเอียดทุกระบบย่อย

## 10. สรุปข้อค้นพบสำคัญ (Key Findings)

### 10.1 Patterns ที่พบร่วมกันทั้ง 3 ฉบับ
1. **คุณสมบัติ 9 ข้อ** ตาม ม.65-66 มีครบทุกฉบับ
2. **กิจการร่วมค้า** กำหนดเงื่อนไขทุกฉบับ
3. **ลงทะเบียน e-GP** บังคับทุกฉบับ
4. **มูลค่าสุทธิกิจการ** กำหนดทุกฉบับ
5. **ค่าปรับ 0.10%/วัน** อัตราที่ใช้มากที่สุดในงาน IT
6. **ภาษาราชการ** + เลขไทย สม่ำเสมอ

### 10.2 ความแตกต่างตามประเภทงาน
- **MA:** เน้น SLA, อุปกรณ์, PM/CM, Certification
- **Development:** เน้น บุคลากร, Deliverables, IP/Source Code, รับประกัน
- **Data Center:** เน้น ตัวแทนจำหน่าย, ระบบย่อย, PM checklist ละเอียด

### 10.3 ข้อสังเกตเชิงปฏิบัติ
- **ผลงานขั้นต่ำ:** แตกต่างตามวงเงิน (50-60% ของวงเงินโครงการ)
- **ระยะเวลาผลงาน:** ย้อนหลัง 3-5 ปี
- **เอกสารจดทะเบียน:** ออกไม่เกิน 2-6 เดือน
- **การนำเสนอ:** โครงการ Dev มีการ present ต่อคณะกรรมการ
- **Statement of Compliance:** จำเป็นสำหรับงาน MA ที่มี spec อุปกรณ์ชัดเจน

## 11. คำแนะนำสำหรับการตรวจสอบ TOR

### Check Items เพิ่มเติมจากตัวอย่างจริง:
- [ ] มีตาราง Statement of Compliance หรือไม่ (งาน MA/สินค้า)
- [ ] ผลงานขั้นต่ำ สมเหตุสมผลกับวงเงิน (30-60%)
- [ ] ระบุ Certification ช่างเทคนิค (งาน IT MA)
- [ ] มีหนังสือรับรองตัวแทนจำหน่าย (งาน Data Center)
