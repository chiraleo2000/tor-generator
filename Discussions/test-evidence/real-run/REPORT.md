## 1) สกก. edit ทดสอบ.docx

ชนิดจริง: แบบขอตั้งงบดิจิทัล ไม่ใช่ TOR เต็มฉบับ  
สกัด 34,635 ตัวอักษร ใน 0.5 วินาที

### ตรวจสอบ — สำเร็จ

- คะแนนรวม **28/100** · ข้อหา 24 ข้อ · ใช้เวลา ~313.5 วินาที (LLM ช้าเพราะ Bedrock throttle)
- ประเมินรวม: ตรวจ 8 ส่วน พบข้อเสนอ compliance ต้องแก้ก่อนถือว่าครบ
- คะแนนย่อย: กฎหมาย **0** (ดึงคะแนนรวมลงมากที่สุด) · lock-in **80** · บริหารโครงการ **75**

ข้อหาสำคัญ:

- ไม่มีทุนจดทะเบียน — ระบบคำนวณจากงบ 5,730,000 ÷ 4 = **1,432,500 บาท**
- ไม่มีค่าปรับ / ไม่มีการรับประกัน / ไม่มีคุณสมบัติผู้เสนอราคาเป็นหมวด TOR
- ไม่ได้อ้าง พ.ร.บ. จัดซื้อจัดจ้างฯ 2560
- ไม่แยกราคากลางจากวงเงิน และไม่ระบุวิธีจัดซื้อ
- Lock-in ที่จับได้: ระบุยี่ห้อ **Google** โดยไม่มี «หรือเทียบเท่า»
- บริหารโครงการ: ไม่มี SLA, ไม่มีเงื่อนไขเข้าพื้นที่, ไม่ระบุสิ่งที่ผู้ว่าจ้างต้องจัดให้

หมายเหตุคุณภาพ: ในแบบฟอร์มมีตารางฮาร์ดแวร์ **Dell / Lenovo / Hitachi / HP / HPE** ชัดเจน แต่ตัวตรวจจับ lock-in **ไม่ฟ้องยี่ห้อเหล่านี้** ฟ้องแค่ Google — โชว์จุดอ่อนของกฎ

### วิเคราะห์ — สำเร็จ (~1 วินาที)

## 2) ร่าง TOR Amazon Quick … (3).pdf

สกัด 20,000+ ตัวอักษร (preview) ใน 0.3 วินาที  
ข้อความไทยเพี้ยนสระ (กำ/กา) แบบ PDF encoding

เนื้อหาที่อ่านได้: จ้างพัฒนาระบบประมวลผลภาวะเศรษฐกิจสังคมครัวเรือนและแรงงานเกษตร + แท็บเล็ต 40 เครื่อง, ทุนจดทะเบียน 2,000,000 บาท, ผลงานไม่น้อยกว่า 2,865,000 บาท, ส่งมอบ 210 วัน, แท็บเล็ตเครื่องละ 22,000 รวม 880,000 บาท  
ในข้อความที่สกัด **ไม่พบคำว่า Amazon / Quick / AWS**

### ตรวจสอบ — สำเร็จ

- คะแนนรวม **38/100** · ข้อหา 15 ข้อ · ~324.5 วินาที
- กฎหมาย **20** · lock-in **100 (ไม่พบ)** · บริหารโครงการ **65**

ข้อหาสำคัญ:

- ไม่พบบประมาณใน metadata (ทั้งที่ในเนื้อหามีตัวเลขแท็บเล็ต/วงเงิน แต่สระเพี้ยน + map หมวดพลาด)
- บอกว่าไม่มีค่าปรับ / ไม่มีกำหนดส่งมอบ / ไม่มีหลักเกณฑ์คัดเลือก / ไม่มีงวดงาน — **บางข้อเป็น false positive** เพราะข้อความอยู่แต่ระบบจัดหมวดไม่เจอ (encoding)
- บอกว่าไม่อ้าง พ.ร.บ. ทั้งที่ในไฟล์มีประโยคอ้างกฎหมาย แต่สะกดเพี้ยน
- Lock-in 100: **ไม่จับแพลตฟอร์ม Amazon Quick** เพราะชื่อไม่อยู่ในข้อความที่สกัด

### วิเคราะห์ — สำเร็จ (~1 วินาที)

สรุป: ขาดหมวด s5, s11, s8 — คะแนนถูกดึงจากกฎหมาย 20/100  
เว็บค้น 0 แหล่ง

## 4) ร่าง จากประกาศจริง

โครงการที่อ่านได้จากเอกสาร (ไม่ใช่ของเล่น):

- **ชื่อ:** โครงการพัฒนาระบบฐานข้อมูลงานติดตามและประเมินผลด้านเศรษฐกิจการเกษตร
- **หน่วยงาน:** ศูนย์ประเมินผล สำนักงานเศรษฐกิจการเกษตร (สศก.)
- **วิธี:** ประกวดราคาอิเล็กทรอนิกส์ (e-bidding)
- **วงเงินในเอกสาร:** **7,920,600 บาท** (รวม VAT) — พัฒนาระบบ 5,736,600 + SQL Server Standard 600,000 ฯลฯ

- **รับประกัน:** ไม่น้อยกว่า 3 ปี (จากประกาศ)

## Blockers / bugs ที่เจอจากรันจริง

1. **Bedrock โควต้าโทเคนรายวันหมด** — คลาส `ThrottlingException` ข้อความ `Too many tokens per day`  
   ตรวจ/วิเคราะห์สามฉบับทำทันก่อนโควต้าหมด (rule engine ไม่พึ่ง LLM) แต่ ReviewAgent และร่างหมวดพึ่ง LLM
2. **อัปโหลด `.xlsx` เป็น HTTP 500** แทนข้อความ validation — `action_plan.xlsx` ใช้ไม่ได้
3. **สกัด PDF ไทยสระเพี้ยน** ทำให้กฎพลาดทั้ง พ.ร.บ. ที่มีอยู่แล้ว และงบ/ค่าปรับที่อยู่แล้ว
4. **Lock-inพลาดยี่ห้อฮาร์ดแวร์** ในแบบ สกก. (Dell/HP/Lenovo) แต่จับ Google/กูเกิลได้
5. **งบถูก infer ผิด** ในฉบับ local (27,001 บาท)
6. **วิเคราะห์: ค้นเว็บ 0 แหล่ง** ทุกหมวด — แผงข้อเสนอแนะไม่มีแหล่งออนไลน์

8. Intake วางข้อความผิดช่อง (s2 ← log, s5 ← คำถามแชท, s18 ปน TOR ของ **กรมป้องกันและบรรเทาสาธารณภัย** จากคลัง — ไม่ใช่โครงการ สศก.)
