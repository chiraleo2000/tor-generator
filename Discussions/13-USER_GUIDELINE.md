## 1. เข้าสู่ระบบ

1. เปิด http://localhost:3000 — ระบบพาไป `/login` อัตโนมัติ
2. กรอก **อีเมล** เช่น `officer@example.go.th`
3. กรอก **รหัสผ่าน** `Passw0rd!`
4. กดปุ่มน้ำเงิน **เข้าสู่ระบบ**
5. เซสชันเก็บในคุกกี้ `tor_access_token` (HttpOnly, SameSite=Lax) — ไม่เก็บ JWT ใน localStorage
6. ระบบพาไปแดชบอร์ด `/projects`

กล่องเทาใต้ปุ่มคือบัญชี Demo ของเจ้าหน้าที่  
ลิงก์ล่างการ์ด **ยังไม่มีบัญชี? สมัครสมาชิก** ไปหน้าสมัคร

![ขั้นที่ 1 — หน้าเข้าสู่ระบบ](test-evidence/00-login.png)

ถ้าไม่กรอกรหัสผ่าน ระบบแสดงข้อความว่าต้องใส่รหัสผ่าน  
ถ้าอีเมล/รหัสผิด จะมีแถบข้อผิดพลาดบนฟอร์ม ไม่เข้าแดชบอร์ด

## 2. สมัครสมาชิก (ถ้ายังไม่มีบัญชี)

1. จากหน้าเข้าสู่ระบบ กด **สมัครสมาชิก** หรือเปิด `/register`
2. กรอก **ชื่อ-นามสกุล**, **อีเมล**, **รหัสผ่าน**, **ยืนยันรหัสผ่าน**, **หน่วยงาน**

4. กดสมัคร ระบบพาไป `/login?registered=true` แล้วเข้าสู่ระบบตามปกติ

บัญชีใหม่ได้บทบาทเจ้าหน้าที่ตามค่าเริ่มต้น ผู้ดูแลเปลี่ยนบทบาทได้ที่หน้าผู้ใช้

## 3. แดชบอร์ดหลังเข้าสู่ระบบ

หัวข้อหน้า: **แดชบอร์ด** — ภาพรวมโครงการ TOR ทั้งหมด  
มุมขวาบนแสดงอีเมลที่ล็อกอิน

### แถบซ้าย (ใช้ทุกหน้า)

| กลุ่ม | เมนู | ไปที่ |
|--------|------|--------|
| หลัก | แดชบอร์ด | `/projects` |
| หลัก | ฐานความรู้ | `/knowledge-base` |
| การทำงาน | ร่าง TOR | โครงการร่างล่าสุดหรือแดชบอร์ด |
| การทำงาน | ตรวจสอบ TOR | `/review` |
| การทำงาน | ถาม-ตอบ | `/chat` |
| อื่นๆ | คู่มือ | `/help` |

บัญชีแอดมินเห็นกลุ่ม **ผู้ดูแลระบบ** เพิ่ม: แม่แบบ, ฐานความรู้ (จัดการ), ผู้ใช้, การตั้งค่า AI

ท้ายแถบ: *OCR/NLP + RAG + Gemma ในเครื่อง — โหมด on-prem ไม่ส่งข้อมูลออก*  
ออกจากระบบ: ลิงก์ **ออกจากระบบ** สีแดงท้ายแถบซ้ายเท่านั้น (มุมขวาบนเป็นอีเมลกับตัวอักษรชื่อ ไม่มีปุ่มประตู)

### ความหมายของสถานะในตาราง

| สถานะในระบบ | ป้ายที่เห็น | ความหมาย |
|--------------|-------------|----------|
| `draft` | ร่าง | เจ้าหน้าที่แก้ 5 Phase ได้ |
| `in_review` | กำลังดำเนินการ | ส่งขออนุมัติแล้ว — ปุ่มแก้ไขถูกปิด |
| `approved` | เสร็จแล้ว | ผู้ตรวจสอบ/แอดมินอนุมัติแล้ว มีปุ่ม **ดู** / **ปรับปรุง** |
| `rejected` | ส่งกลับ | ผู้ตรวจสอบส่งกลับ — ส่งขออนุมัติใหม่ได้ |
| `archived` | เก็บถาวร | กด **ลบ** จากตาราง (เก็บถาวร ไม่ใช่ลบไฟล์ถาวรจากดิสก์ทันที) |

การ์ดสามใบนับ `draft` / `in_review` / `approved` ตามลำดับ **ร่าง / กำลังดำเนินการ / เสร็จแล้ว**

### ตารางรายการโครงการ TOR

คอลัมน์: ชื่อโครงการ, หน่วยงาน, งบประมาณ (บาท), สถานะ, วันที่อัปเดต (พ.ศ.), การกระทำ (**แก้ไข** / **ลบ**)  
โครงการที่กำลังประมวลผลปุ่มแก้ไขจะกดไม่ได้

## 4. สร้างโครงการ TOR ใหม่

1. กดปุ่มล่างขวา **+ สร้างโครงการ TOR ใหม่**
2. กรอกฟอร์มในกล่อง **สร้างโครงการใหม่** (กระบวนการ 5 Phase ไม่ใช่วิซาร์ด 8 ขั้น)
3. ฟิลด์:
   - **ชื่อโครงการ** (บังคับ)
   - **หน่วยงาน** (บังคับ)
   - **วงเงินงบประมาณ** — ตัวเลข ASCII `0-9` ใส่จุลภาคได้ เช่น `100,000` (เลขไทย `๑๒๓` ใช้ไม่ได้)
   - **ประเภทงาน** — ระบบเทคโนโลยีสารสนเทศ / งานก่อสร้าง / งานจ้างที่ปรึกษา / จัดซื้อจัดจ้างทั่วไป
   - **แม่แบบ** — เลือกได้ถ้าผู้ดูแลเผยแพร่แม่แบบแล้ว
4. ถ้าขาดชื่อ หน่วยงาน หรืองบประมาณ ระบบขึ้น *กรุณากรอกชื่อโครงการ หน่วยงาน และงบประมาณ*
5. กด **สร้างโครงการ** ระบบพาไป `/projects/{id}/draft` ที่ **Phase 0**

![ขั้นที่ 4 — ฟอร์มสร้างโครงการ](test-evidence/02b-create-dialog.png)

## 5. กระบวนการร่าง 5 Phase

พื้นที่ทำงานอยู่ที่ `/projects/{id}/draft`  
แถบด้านบนของโครงการมีวงกลม Phase 0–4 — **คลิกข้ามไป Phase 3 ไม่ได้** จนกว่าจะวิเคราะห์แล้วตอบส่วนขาด และกดพร้อมร่าง TOR

เส้นทางเก่า `/wizard/...` เปลี่ยนเส้นทางมาที่นี่อัตโนมัติ

| Phase | ชื่อบนแถบ | สิ่งที่ทำ |
|-------|-----------|-----------|
| 0 | เตรียมข้อมูล | อัปโหลดหรือวางข้อความได้หลายครั้ง — ต้องกด **เริ่มวิเคราะห์** จึงจะประมวลผล |
| 1 | วิเคราะห์ความต้องการ | ตารางความครบถ้วนจากผลวิเคราะห์ แล้วนับสั้น ๆ หรือกด **ไปเลย** เข้า Phase 2 — ไม่มีไดอะล็อก และไม่ดึงกฎหมายอัตโนมัติ |
| 2 | สอบถามเพิ่ม | ตารางสถานะคู่แชทถามช่องข้อเท็จจริงที่ขาด ติ๊ก **แนบอ้างอิงกฎหมายประกอบคำตอบนี้** ตอนส่งคำตอบเท่านั้น แล้วกดพร้อมร่าง TOR |
| 3 | ร่างเนื้อหา TOR | ระบบร่างทั้ง 13 หมวดอัตโนมัติถ้ายังไม่ครบ แก้/ยอมรับผ่านแชท ยืนยัน HITL แล้วกด **ไปทบทวน (Phase 4)** |
| 4 | ทบทวนและเผยแพร่ | แชทรีวิว + Rule Engine รันอัตโนมัติเมื่อเข้าขั้น ส่งขออนุมัติ ส่งออก Word/PDF |

### 5.1 Phase 0 — วางข้อความหรืออัปโหลดชุดเอกสาร

1. อ่านข้อความบนการ์ด: **ต้องมีข้อความร่างหรือไฟล์ก่อน** จึงจะไปร่าง 13 หมวดได้
2. วางข้อความในช่อง หรือคลิกอัปโหลดไฟล์ PDF / Word / ภาพสแกน ทั้งชุดในครั้งเดียว
3. ระหว่างอัปโหลดเห็น **กำลังอัปโหลด...** และชื่อไฟล์ แล้วกด **เริ่มวิเคราะห์และเข้า Phase 1** — ระบบ**จะไม่วิเคราะห์อัตโนมัติ**ตอนอัปโหลด ต้องยืนยันในกล่องโต้ตอบก่อน
4. หลังยืนยัน หน้า Phase 0 กลายเป็นแผง progress (อย่าปิดหน้านี้) จน API กลับมา จึงเข้า Phase 1
5. ต้นฉบับเก็บใน MongoDB GridFS แล้วสกัดข้อความ ฝังด้วย EmbeddingGemma — ยังไป Phase 3 ไม่ได้จนกว่าจะกดพร้อมร่าง

**อย่าเริ่มจากเมนู ร่าง TOR (`/draft`) ถ้ายังไม่มีโครงการ** — หน้านี้ถ้าไม่มีร่าง จะสร้างโครงการชื่อ `โครงการใหม่ #1` งบ 1 บาททันที โดยไม่เปิดฟอร์ม ใช้ปุ่มบนแดชบอร์ดแทน

ถ้าไฟล์เป็นภาพสแกนที่ไม่มี OCR ให้ใส่ไฟล์ที่มีข้อความคัดลอกได้ หรือเปิด Tesseract ในสแตก

![ขั้นที่ 5.1 — Phase 0 อัปโหลดชุดใหญ่ในแชท](test-evidence/03-phase-0-upload.png)

### 5.2 Phase 1 — ตารางความครบถ้วนแล้วไปคุยต่อ

1. ดู **ตารางความครบถ้วน** — สถานะ `filled` / `gap` / `reference_only` จากผลวิเคราะห์ ไม่ดึงกฎหมายทั้งชุดอัตโนมัติ
2. ระบบนับถอยหลังสั้น ๆ แล้วไป Phase 2 เอง หรือกด **ไปเลย** (`phase1-skip`) — **ไม่มี**ไดอะล็อกยืนยัน
3. คลิกวงกลม Phase 0 ถ้าต้องอัปโหลดเพิ่ม

![ขั้นที่ 5.2 — ตารางความครบถ้วนหลังแกะเอกสาร](test-evidence/04b-phase-1-coverage.png)

### 5.3 Phase 2 — ถามส่วนขาดและยืนยันพร้อมร่าง

พื้นที่เป็นตารางสถานะจาก Phase 1 คู่แชทโครงการ (บอทถามช่องข้อเท็จจริงที่ขาดทีละข้อ)

1. บอทถามทีละช่องที่ขาด — ตอบในแชทเพื่อใส่เป็นข้อเท็จจริงของโครงการ
2. ถ้าต้องการอ้างกฎหมายประกอบคำตอบที่บอทถามอยู่ ให้ติ๊ก **แนบอ้างอิงกฎหมายประกอบคำตอบนี้** ตอนส่ง — ค่าเริ่มต้นปิด และ**ไม่มีชิป/ปุ่มดึงอ้างอิงต่อแถว**
3. ช่องบังคับด้านข้อเท็จจริง (เช่น ชื่อโครงการ วัตถุประสงค์ วงเงิน ระยะเวลา สถานที่ สรุปงาน) ต้องเป็น `filled` จากเอกสารหรือคำตอบผู้ใช้ — `reference_only` อย่างเดียวไม่พอ
4. เมื่อข้อเท็จจริงหลักครบ กด **ครบแล้ว — ไปร่าง TOR (Phase 3)** ระบบตั้ง `ready_to_compose` (มีไดอะล็อกยืนยัน)

![ขั้นที่ 5.3 — Phase 2 ตารางคู่แชท](test-evidence/e2e-phase-2-qa.png)

### 5.4 Phase 3 — ร่างเนื้อหา 13 หมวด

1. แถบแสดง **Phase 3: ร่างเนื้อหา TOR — คุยแล้วให้ระบบร่าง**
2. ระบบร่างทั้ง 13 หมวดอัตโนมัติถ้ายังไม่มีเนื้อหา — ถ้าครบแล้วจะ**ไม่**เรียก `/draft-chat/start` ทับใหม่
3. แก้หรือขอร่างใหม่ผ่านแชท แล้วกดยอมรับในแชทเพื่อบันทึก `is_approved`
4. หมวด 4 ขอบเขตของงานมีชิปย่อย 4.1–4.14 (สรุปงาน, As-Is, ฮาร์ดแวร์, ซอฟต์แวร์, ฯลฯ)
5. กด **ร่างด้วย AI** ที่หมวดเดี่ยวได้ถ้าต้องการเขียนทับช่องนั้น แล้ว **บันทึกหมวดนี้**

**หมวดที่ต้องให้เจ้าหน้าที่ยืนยัน (HITL)** — สถานะ *ยังไม่กรอก - ต้องให้เจ้าหน้าที่ยืนยัน*:

| รหัส | หมวด |
|------|------|
| s3 | คุณสมบัติของผู้เสนอราคา |
| s6 | วงเงินงบประมาณ |
| s8 | งวดงานและการจ่ายเงิน |
| s10 | อัตราค่าปรับ |
| s13 | เงื่อนไขอื่น ๆ |

หลังตรวจเนื้อหา กด **เจ้าหน้าที่ยืนยันแล้ว** ในหมวดนั้น จึงนับว่าอนุมัติโดยคน — ปุ่มนี้อยู่ใต้ปุ่มบันทึกเมื่อหมวดนั้นถูกขยาย

### 5.5 Phase 4 — ทบทวนและอนุมัติ

1. ดูแถบความครบถ้วน เช่น `13/13 หมวด` และแถบสีตามเปอร์เซ็นต์
2. ถ้ายังไม่ครบ: แถบเตือน *ยังกรอกไม่ครบทุกหมวด* — กลับ Phase 3 กรอกจนครบ 13 หมวด
3. ถ้ายังไม่กดยืนยัน HITL: แถบ *ยังไม่ได้ยืนยันหมวด HITL* — ปุ่ม **ส่งขออนุมัติ / สร้าง TOR** กดไม่ได้จนกว่าจะครบทั้ง 13 หมวด **และ** ยืนยัน HITL ครบ 5 หมวด
4. **Rule Engine รันอัตโนมัติเมื่อเข้า Phase 4** แล้วแสดง *คะแนนคุณภาพ …/100* พร้อม findings — กด **รัน Rule Engine** ได้ถ้าต้องการตรวจอีกครั้ง หรือพิมพ์ในแชทรีวิวว่า `ตรวจอีกครั้ง` / `ยืนยันหมวด 6`
5. กด **ส่งขออนุมัติ / สร้าง TOR** — สถานะเป็น `in_review` (ป้าย **กำลังดำเนินการ**) ระบบพากลับแดชบอร์ด ปุ่มแก้ไขถูกปิดจนกว่าผู้ตรวจสอบจะตัดสิน
6. กด **ย้อนกลับไปแก้ไข** ถ้ายังไม่พร้อมส่ง

### 5.7 ถาม-ตอบ (`/chat`)

เครื่องมือที่ 3 ในกลุ่มการทำงาน — **ไม่ปนประวัติกับแชทร่างโครงการ**

1. กดเมนู **ถาม-ตอบ** เปิด `/chat`
2. คอลัมน์ซ้ายเป็นห้องย่อ (~260px): ชื่อ, ข้อความล่าสุด, เวลา — ปุ่มห้องใหม่ / ค้นหา / ยุบแถบ
3. เมนูจุดสามจุดต่อห้อง: เปลี่ยนชื่อ, ลบ
4. แนบไฟล์เข้าคลังส่วนตัว (Mongo GridFS + `ingest_file_bytes` เฉพาะบัญชีนี้) แล้วเห็นข้อความสำเร็จ/ล้มเหลวจากผล ingest เช่น *เพิ่มเข้าคลังของฉันแล้ว — ใช้กับ RAG ได้*
5. สลับแหล่งค้นด้วยไอคอน: คลังกลาง / ของฉัน / ทั้งคู่ — โหมดของฉันไม่ค้นคลังกลางและไม่รั่วเอกสารของคนอื่น
6. ระหว่างรอโทเคน SSE มีจุดพิมพ์; ข้อความแสดงเวลาเมื่อ API ส่ง `created_at`
7. คำตอบมีชิปอ้างอิง (เอกสาร / มาตรา / หมวด TOR) ชี้กลับไฟล์ต้นฉบับใน Mongo
8. ค่าเริ่มต้นยังเป็น Gemma จาก LM Studio — ไม่มีแท็บโมเดลคลาวด์ในหน้านี้ (สลับที่การตั้งค่า AI)

คลังกลาง seed จาก PDF ใน `documents/sources/` ด้วย `python -m app.seed_raw_docs` จากโฮสต์ (ไม่ ingest JSON extracts เก่า)

## 6. ฐานความรู้ (ผู้ใช้ทั่วไป)

1. กด **ฐานความรู้** ในแถบซ้าย (`/knowledge-base`)
2. เลือกหมวดที่จะดู: กฎหมาย/ระเบียบกลาง, ประกาศราคากลาง / ระเบียบ, ร่างเอกสารประกวดราคา, ความต้องการ/คู่มือ, กฎกระทรวง

4. เจ้าหน้าที่กด **อัปโหลดเอกสารของฉัน** ที่หน้านี้ (`POST /knowledge-base/mine`) — ไฟล์ถูก chunk/embed เฉพาะบัญชีนั้น เจ้าหน้าที่อื่นไม่เห็น · หมวดรวม **ข้อมูลอื่น ๆ** · แต่ละไฟล์แสดงสถานะประมวลผล
5. ผู้ดูแลอัปโหลดคลังกลางที่หัวข้อ **อัปโหลดเอกสารเข้าคลังความรู้ส่วนกลาง** (หรือหน้าฐานความรู้จัดการ)

## 7. ตรวจสอบ TOR และอนุมัติโครงการ

มีสองทางที่ไม่ใช่หน้าเดียวกัน

| ทาง | เมนู | ใช้เมื่อ |
|-----|------|----------|
| 7.1 ตรวจไฟล์ภายนอก | **ตรวจสอบ TOR** `/review` | มีไฟล์ Word/PDF อยู่แล้ว ไม่ต้องสร้างโครงการ |
| 7.2 อนุมัติร่างในระบบ | แดชบอร์ด (บัญชีผู้ตรวจสอบ/แอดมิน) | เจ้าหน้าที่กดส่งขออนุมัติจาก Phase 3 แล้ว |

### 7.1 ตรวจไฟล์ TOR ภายนอก (Rule Engine + เทียบเคียง)

1. กด **ตรวจสอบ TOR**
2. การ์ดซ้าย: ลากไฟล์หลัก PDF / Word / ภาพสแกน — เห็นชื่อไฟล์และขนาด KB
3. เอกสารอ้างอิงบังคับห้ามปิด (ใช้ตอนรันกฎเสมอ):
   - พ.ร.บ. การจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560
   - ระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างฯ พ.ศ. 2560
   - คู่มือการจัดซื้อจัดจ้างตาม พ.ร.บ. 2560
   - มาตรฐาน e-Bidding กรมบัญชีกลาง
   - ประกาศราคากลาง (จากคลังความรู้)
4. (ไม่บังคับ) กด **+ เพิ่มโครงการเปรียบเทียบ** ตั้งชื่อ แล้วอัปโหลดไฟล์คู่เทียบได้หลายไฟล์ — ปุ่ม **ลบ #n** เอาแถวออก
5. กด **สกัดข้อความ** (กดไม่ได้จนกว่าจะมีไฟล์หลัก) แล้วตรวจตัวอย่างข้อความ
6. กด **ยืนยันเริ่มตรวจสอบ** จึงรัน Rule Engine (ระหว่างรันปุ่มเป็น *กำลังตรวจสอบ...*)
7. ระบบทำตามลำดับ:
   1. สกัดข้อความไฟล์หลัก (`POST /review/extract`) — สถานะ *สกัดข้อความสำเร็จ*
   2. สกัดไฟล์คู่เทียบแต่ละไฟล์
   3. เทียบ Jaccard (`POST /review/compare-projects` ด้วย `extract_ids`)
   4. รัน Rule Engine (`POST /review/run`)
8. การ์ดขวา **ผลการตรวจสอบ**:
   - คะแนนความพร้อม `…/100` — ต่ำกว่า 70 แสดงว่ายังไม่ผ่านเกณฑ์เบื้องต้น
   - รายการพบ: **error** = ไม่ผ่าน (แดง), **warning** = เตือน, อื่น ๆ = ผ่าน/ข้อเสนอ
   - แต่ละข้อแสดงข้อความและคำแนะนำหรือรหัสหมวด — ไม่โชว์ `[object Object]`
   - แถวเทียบเคียง: *เทียบเคียง ไฟล์A กับ ไฟล์B* ค่า Jaccard `0.0000–1.0000` (ตั้งแต่ 0.5 ขึ้นไปถือว่าใกล้เคียง)
   - ถ้าตรวจล้มเหลว มีข้อความ `role="alert"` ไม่ใช้สีเขียวปนกับข้อผิดพลาด

ถ้า API เทียบเคียงตอบ 404/405/501 แอปจะคำนวณ Jaccard ในเบราว์เซอร์จากข้อความที่สกัดได้

### 9.1 แม่แบบ

หน้า **จัดการแม่แบบ**

1. กรอกชื่อ ประเภทงาน (IT / ก่อสร้าง / ที่ปรึกษา / ทั่วไป)
2. ตรวจ JSON โครงสร้าง 13 หมวด และคำแนะนำช่องว่าง
3. กด **สร้างร่าง** (หรือบันทึกเมื่อแก้ไข)
4. กดเผยแพร่แม่แบบที่ต้องการ — ฟอร์มสร้างโครงการจะเลือกได้เฉพาะสถานะเผยแพร่
5. ยกเลิกเผยแพร่ถ้ามีโครงการใช้อยู่ ระบบเตือนจำนวนที่กระทบ ต้องกดยืนยันอีกครั้ง

![ขั้นที่ 9.1 — จัดการแม่แบบ](test-evidence/16-admin-templates.png)

### 9.2 ฐานความรู้ (จัดการ)

ลาก PDF / DOCX / TXT เข้าคลังกลาง หรือสั่งประมวลผลใหม่ทั้งชุด  
ถ้าเปลี่ยนโมเดล embeddings ต้อง `python -m app.seed_raw_docs` อีกครั้ง (อย่า ingest JSON extracts เก่า)

![ขั้นที่ 9.2 — ฐานความรู้ฝั่งผู้ดูแล](test-evidence/17-admin-kb.png)

### 9.3 ผู้ใช้ระบบ

1. กรอกชื่อ อีเมล รหัสผ่าน หน่วยงาน บทบาท (เจ้าหน้าที่ / ผู้ตรวจสอบ / ผู้ดูแลระบบ) แล้วกด **สร้างผู้ใช้**
2. ในรายการ: เปลี่ยนบทบาทจากดรอปดาวน์ได้ทันที
3. กด **ปิดใช้** / **เปิดใช้** เพื่อระงับบัญชี
4. ลืมรหัสผ่านของเจ้าหน้าที่: สร้างบัญชีใหม่หรือตั้งรหัสตอนสร้าง — หน้านี้ยังไม่มีปุ่มรีเซ็ตรหัสของแถวที่มีอยู่

![ขั้นที่ 9.3 — ผู้ใช้ระบบ](test-evidence/18-admin-users.png)

### 9.4 การตั้งค่า AI

1. เปิด **การตั้งค่า AI**
2. โหมด (`on_prem` / `cloud` / `hybrid`) เป็นป้ายกำกับเท่านั้น — **ไม่สลับคู่** แชทกับ embeddings
3. ค่าเริ่มต้นแชท LM Studio `google/gemma-4-e4b` embeddings `text-embedding-embeddinggemma-300m` timeout 180 คลังเวกเตอร์ `pgvector`
4. เลือกแชทและ embeddings คนละแหล่งได้ เช่น Claude API + EmbeddingGemma ในเครื่อง (`LOCAL_EMBEDDING_SERVER=lm_studio`)
5. กด **ทดสอบการเชื่อมต่อ** — ยิงทั้งแชทและ embeddings คนละปลายทางได้ (ไม่ต้องรีสตาร์ท)
6. กด **บันทึก** — มีผลทันทีในกระบวนการร่าง (ไม่ต้องรีสตาร์ท backend)

ถ้าเปลี่ยนผู้ให้บริการหรือชื่อโมเดล embeddings ระบบเตือนให้รัน `python -m app.seed_raw_docs`

![ขั้นที่ 9.4 — โหมดในเครื่องและ ping สำเร็จ](test-evidence/09-admin-ai-lm-studio.png)

![ขั้นที่ 9.4 — ฟอร์มเซิร์ฟเวอร์ในเครื่อง](test-evidence/09a-admin-ai-local.png)

**คลาวด์** — เลือก Claude / OpenAI / Gemini / Amazon Bedrock / Azure AI Foundry / อื่น ๆ (OpenAI-compatible) ใส่ API key ในหน้านี้ได้ ไม่ต้องใส่ใน `.env` และไม่บังคับสลับ embeddings  
**ผสม** — แนะนำเมื่อใช้คนละแหล่งชัดเจน คลาวด์ต้องมีคีย์ของฝั่งที่เลือก

#### สูตรที่ใช้บ่อย (แชทและฝังเวกเตอร์เลือกคนละช่อง)

| เป้าหมาย | โหมด | โมเดลแชท | ฝังเวกเตอร์ | คีย์ / เซิร์ฟเวอร์ | ต้อง seed ใหม่? |
|----------|------|-----------|-------------|-------------------|----------------|
| Claude + EmbeddingGemma ในเครื่อง | ผสม | Claude (Anthropic) | ในเครื่อง | Anthropic API key + LM Studio :1234 โหลด `text-embedding-embeddinggemma-300m` · URL จาก Docker = `http://host.docker.internal:1234/v1` | ไม่ (ถ้าเคยใช้ EmbeddingGemma อยู่แล้ว) |
| Claude + OpenAI embeddings | ผสม หรือ คลาวด์ | Claude (Anthropic) | ฝังเวกเตอร์ OpenAI | Anthropic + OpenAI API key · โมเดลฝังเวกเตอร์ OpenAI ค่าเริ่มต้น `text-embedding-3-small` | **ใช่** — รัน `python -m app.seed_raw_docs` หลังบันทึก |
| Gemma ในเครื่อง (ค่าเริ่มต้น) | รันในเครื่อง | LM Studio | ในเครื่อง | LM Studio โหลดทั้ง `google/gemma-4-e4b` และ EmbeddingGemma | ไม่ |

ขั้นตอนสั้น ๆ สำหรับ **Claude + ฝังเวกเตอร์ในเครื่อง**: (1) โหมด **ผสม** (2) แชท = Claude · ฝังเวกเตอร์ = ในเครื่อง (3) ใส่ Anthropic API key (4) ตั้ง LM Studio URL และชื่อโมเดลฝังเวกเตอร์ (5) **ทดสอบการเชื่อมต่อ** แล้ว **บันทึก** — ไม่ต้องรีสตาร์ท backend

Claude ใช้โมเดล `claude-sonnet-4-20250514` ในโค้ด (ไม่มีช่องเปลี่ยนชื่อในหน้านี้) · ช่อง **ชื่อโมเดลแชท** ใช้เมื่อเลือก LM Studio/Ollama เท่านั้น
