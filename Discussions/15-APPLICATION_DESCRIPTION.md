# คำอธิบายแอปพลิเคชัน — ระบบจัดทำและตรวจสอบ TOR

ระบบช่วยเจ้าหน้าที่พัสดุร่างและตรวจสอบเอกสารขอบเขตของงาน (Terms of Reference) ตามพระราชบัญญัติการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560

เอกสารชุดปัจจุบันของสแตก Docker + LM Studio Gemma คือ **13–18** (คู่มือ, ติดตั้ง, คำอธิบายแอป, backend, frontend, หลักฐานเทสต์)  
ชุด `01`–`12` เป็นบันทึกออกแบบก่อนหน้า รวม PoC HTML — อย่าใช้ `10`/`11` เป็นคู่มือติดตั้งของแอปที่รันอยู่

## ปัญหาที่แก้

การเขียน TOR ด้วยมือใช้เวลานาน ตกหล่นหัวข้อกฎหมาย และจัดรูปแบบราชการยาก ระบบนี้บังคับโครงสร้าง 13 ส่วน (s1–s13) รับชุดเอกสารในแชท จัดเข้าช่อง ตรวจด้วย Rule Engine แล้วส่งออก Word/PDF ตามมาตรฐานราชการ (TH Sarabun New, วันที่ พ.ศ.)

## ผู้ใช้

- **เจ้าหน้าที่ (officer)** — สร้างโครงการด้วยฟอร์ม (ชื่อ หน่วยงาน วงเงิน ประเภท แม่แบบ) แล้วร่าง 5 Phase ส่งตรวจ ส่งออก ตรวจไฟล์ภายนอก และถาม-ตอบคลังความรู้
- **ผู้ตรวจสอบ (reviewer)** — ดูโครงการทั้งหมด อนุมัติหรือส่งกลับ
- **ผู้ดูแลระบบ (admin)** — แม่แบบ ฐานความรู้ (จัดการ) ผู้ใช้ และการตั้งค่า AI (Local / Cloud / Hybrid)

## ความสามารถหลัก

1. พื้นที่ทำงาน **5 Phase (0–4)** ที่แมปไปยัง s1–s13 (หมวด 4 มีหัวข้อย่อย 4.1–4.14)
2. **Phase 0–1 เป็นแชทโครงการ** — อัปโหลดหลายไฟล์ได้โดยไม่ต้องเลือก 9 ประเภท ต้นฉบับเก็บใน MongoDB GridFS แล้วจัดเข้าช่อง s1–s13 / s4.1–s4.14 ตารางความครบถ้วน ถามส่วนขาด ดึงอ้างอิงกฎหมาย แล้วกดพร้อมร่าง
3. **ถาม-ตอบคลังความรู้** ที่ `/chat` — ห้องย่อแบบ Open WebUI, SSE, ชิปอ้างอิง, แนบไฟล์เข้าคลังส่วนตัว ไม่ปนประวัติกับแชทร่าง
4. ร่างด้วย AI ใน Phase 2: แต่ละหมวดเรียกเอเจนต์ s1–s13 ค่าเริ่มต้น LM Studio + Gemma + EmbeddingGemma-300M หรือคลาวด์เมื่อผู้ดูแลเปิดใช้ (Anthropic, OpenAI, Gemini, Bedrock, Azure Foundry, OpenAI-compatible)
5. ตรวจคุณภาพ: กฎหมาย / ความครบถ้วน / ความสอดคล้อง / รูปแบบ / งวดจ่าย / ระยะเวลา (กฎงวดจ่ายและไทม์ไลน์ข้ามเมื่อไม่มีข้อมูล)
6. ส่งออก DOCX + PDF — e-Bidding เป็นงานเจ้าหน้าที่นอกแอป ไม่มีช่องติ๊กปลอมใน Phase 4
7. ตรวจไฟล์ TOR ภายนอกโดยไม่สร้างโครงการ — สกัดแล้วเทียบคู่ด้วย Jaccard (`POST /review/compare-projects` รับ `project_ids` และ `extract_ids`)
8. คลังกฎหมายใช้งานมาจาก PDF ใน `documents/sources/` ผ่าน `python -m app.seed_raw_docs` (GridFS + pgvector 768-d + กราฟ Neo4j) — **ไม่ ingest JSON extracts เก่าเป็นคลังหลัก**
9. ค่าเริ่มต้นแบบ on-prem — คลาวด์เป็นทางเลือกจากหน้าการตั้งค่า AI และมีผลทันทีหลังกดบันทึก
10. ผู้ดูแลทดสอบการเชื่อมต่อ AI ได้ทันที โดยไม่ต้องรีสตาร์ท
11. ยืนยันหมวด HITL ก่อนส่งอนุมัติ — ปุ่มส่งขออนุมัติกดไม่ได้จนกว่าจะครบ 13 หมวดและยืนยัน HITL
12. ผู้ตรวจสอบ/แอดมินกด **อนุมัติ** หรือ **ส่งกลับ** บนแดชบอร์ดเมื่อโครงการอยู่ในสถานะกำลังดำเนินการ

## ขอบเขตที่ยังไม่ครบในสภาพแวดล้อมนี้

- หากเซิร์ฟเวอร์ LLM ในเครื่องไม่ได้เปิด Phase 2 / ร่างด้วย AI / แชทถาม-ตอบจะแสดงข้อผิดพลาด แต่ยังกรอกมือและส่งออกจากข้อความที่กรอกได้
- GraphRAG ลดเหลือ pgvector ถ้า Neo4j ไม่ขึ้น — แชทยังตอบได้แต่ไม่มีกราฟ
- ไม่มี e-GP จริง และไม่มี LangGraph checkpointer
- `python -m app.seed_kb` ยังมีสำหรับ extracts งานวิจัย แต่ไม่ใช่คลังที่แอปถาม-ตอบใช้หลังรีเซ็ตรอบนี้
