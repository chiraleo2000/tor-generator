เอกสารชุดปัจจุบันของสแตก Docker + LM Studio Gemma คือ **13–23** (คู่มือ, ติดตั้ง, คำอธิบายแอป, backend, frontend, หลักฐานเทสต์, รายงานการทำงาน, Bedrock ทางลัด, workflow ทั้งสามบริการ)

## ปัญหาที่แก้

การเขียน TOR ด้วยมือใช้เวลานาน ตกหล่นหัวข้อกฎหมาย และจัดรูปแบบราชการยาก ระบบนี้บังคับโครงสร้าง 13 ส่วน (s1–s13) รับชุดเอกสารในแชท จัดเข้าช่อง ตรวจด้วย Rule Engine แล้วส่งออก Word/PDF ตามมาตรฐานราชการ (TH Sarabun New, วันที่ พ.ศ.)

## ผู้ใช้

- **เจ้าหน้าที่ (officer)** — สร้างโครงการด้วยฟอร์ม (ชื่อ หน่วยงาน วงเงิน ประเภท แม่แบบ) แล้วร่าง 5 Phase ส่งตรวจ ส่งออก ตรวจไฟล์ภายนอก ถาม-ตอบคลังความรู้ และอัปโหลดเอกสารของตนเองที่หน้าฐานความรู้ (เฉพาะบัญชีนี้)
- **ผู้ตรวจสอบ (reviewer)** — ดูโครงการทั้งหมด อนุมัติหรือส่งกลับ
- **ผู้ดูแลระบบ (admin)** — แม่แบบ ฐานความรู้ (จัดการ) ผู้ใช้ และการตั้งค่า AI (บน **production AWS ล็อกเป็น Cloud/Bedrock**; ตัวเลือก Local / Hybrid มีไว้สำหรับเครื่องพัฒนา — ดูเอกสาร 29)

## ความสามารถหลัก

1. พื้นที่ทำงาน **5 Phase (0–4)** ที่แมปไปยัง s1–s13 (หมวด 4 มีหัวข้อย่อย 4.1–4.14)
2. **Phase 0–2 เป็น intake ของโครงการ** — อัปโหลดหลายไฟล์ได้ (สูงสุด 50 MB ต่อไฟล์) โดยไม่ต้องเลือก 9 ประเภท ต้นฉบับเก็บใน MongoDB GridFS ผู้ใช้ต้องกด **เริ่มวิเคราะห์** จึงจัดเข้าช่อง s1–s13 / s4.1–s4.14 จากฮิวริสติกแล้ว LLM (ชุดยาวแบ่งก้อน) **ไม่ดึงคลังกฎหมายอัตโนมัติตอนวิเคราะห์** — กด **ใช้มาตรฐานกลางเติมช่องว่าง** ใน Phase 2 (`fill-references` ไม่ทับช่องข้อเท็จจริง) Phase 1 เป็นตารางความครบ **ไม่มีนับถอยหลัง 10 วินาที** กดไปขั้นที่ 2 ได้ทันที Phase 2 มีตารางคู่แชทถามช่องข้อเท็จจริงที่ขาด แล้วกดพร้อมร่าง
3. **ถาม-ตอบคลังความรู้** ที่ `/chat` (`kind=kb`) — ดึง pgvector **32** ชิ้น คละแหล่งสูงสุด **48** ชิ้นในหน้าต่าง Gemma **128,000** โทเคน ตอบแบบบันทึกเจ้าหน้าที่พัสดุ (หลายหัวข้อ) ผ่าน SSE พร้อมชิปอ้างอิง แนบไฟล์เข้าคลังส่วนตัวหมวด **ข้อมูลอื่น ๆ** (`category=other`) แล้วเห็นในหน้าฐานความรู้ได้
4. ร่างด้วย AI ใน **Phase 3**: แต่ละหมวดเรียกเอเจนต์ s1–s13 ค่าเริ่มต้น LM Studio + Gemma + EmbeddingGemma-300M หรือคลาวด์เมื่อผู้ดูแลเปิดใช้ (Anthropic, OpenAI, Gemini, Bedrock, Azure Foundry, OpenAI-compatible)
5. ตรวจคุณภาพ: กฎหมาย / ความครบถ้วน / ความสอดคล้อง / รูปแบบ / งวดจ่าย / ระยะเวลา (กฎงวดจ่ายและไทม์ไลน์ข้ามเมื่อไม่มีข้อมูล)
6. ส่งออก DOCX + PDF ใน **Phase 4** พร้อมแชทรีวิวและ Rule Engine ที่รันอัตโนมัติเมื่อเข้าขั้น — e-Bidding เป็นงานเจ้าหน้าที่นอกแอป ไม่มีช่องติ๊กปลอม
7. ตรวจไฟล์ TOR ภายนอกโดยไม่สร้างโครงการ — **3 ขั้น**: เลือกไฟล์ → สกัดข้อความ → ยืนยันเริ่มตรวจสอบ (`POST /review/extract` แล้ว `POST /review/run`) เทียบคู่ด้วย Jaccard (`POST /review/compare-projects`)
8. คลังกฎหมายใช้งานมาจาก PDF ใน `documents/sources/` ผ่าน `python -m app.seed_raw_docs` (GridFS + pgvector 768-d + กราฟ Neo4j) — **ไม่ ingest JSON extracts เก่าเป็นคลังหลัก**
9. ค่าเริ่มต้นแบบ on-prem สำหรับ **เครื่องพัฒนา** — แชทและ embeddings เลือกอิสระได้ในโค้ด (เช่น Claude API + EmbeddingGemma) แต่ **production บน AWS ห้าม hybrid** (`LLM_PROVIDER=bedrock` และ `EMBEDDING_PROVIDER=bedrock` คู่กัน) คลังถาม-ตอบยังค้นได้ทั้งคลังกลางและเอกสารของฉัน (`both`)
10. ผู้ดูแลทดสอบการเชื่อมต่อทั้งแชทและ embeddings ได้ทันที โดยไม่ต้องรีสตาร์ท
11. ส่งขออนุมัติเมื่อครบ **13 หมวด** (`isSectionFilled`) — ไม่มีปุ่มยืนยัน HITL ทีละหมวดบนจอแล้ว ระบบตั้ง `is_approved` ให้หมวดเสี่ยงตอนกดเข้าทบทวน (`confirm-phase4`) คะแนนกฎ &lt; 70 เป็นคำเตือนไม่ล็อกส่งตรวจ
12. ผู้ตรวจสอบ/แอดมินกด **อนุมัติ** หรือ **ส่งกลับ** บนแดชบอร์ดเมื่อโครงการอยู่ในสถานะกำลังดำเนินการ

## ขอบเขตที่ยังไม่ครบในสภาพแวดล้อมนี้

- หากเซิร์ฟเวอร์ LLM ในเครื่องไม่ได้เปิด Phase 2 / ร่างด้วย AI / แชทถาม-ตอบจะแสดงข้อผิดพลาด แต่ยังกรอกมือและส่งออกจากข้อความที่กรอกได้
- GraphRAG ลดเหลือ pgvector ถ้า Neo4j ไม่ขึ้น — แชทยังตอบได้แต่ไม่มีกราฟ
- ไม่มี e-GP จริง และไม่มี LangGraph checkpointer
- `python -m app.seed_kb` ยังมีสำหรับ extracts งานวิจัย แต่ไม่ใช่คลังที่แอปถาม-ตอบใช้หลังรีเซ็ตรอบนี้
