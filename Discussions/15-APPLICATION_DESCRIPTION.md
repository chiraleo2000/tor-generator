# คำอธิบายแอปพลิเคชัน — ระบบจัดทำและตรวจสอบ TOR

ระบบช่วยเจ้าหน้าที่พัสดุร่างและตรวจสอบเอกสารขอบเขตของงาน (Terms of Reference) ตามพระราชบัญญัติการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560

เอกสารชุดปัจจุบันของสแตก Docker + LM Studio Gemma คือ **13–18** (คู่มือ, ติดตั้ง, คำอธิบายแอป, backend, frontend, หลักฐานเทสต์)  
ชุด `01`–`12` เป็นบันทึกออกแบบก่อนหน้า รวม PoC HTML — อย่าใช้ `10`/`11` เป็นคู่มือติดตั้งของแอปที่รันอยู่

## ปัญหาที่แก้

การเขียน TOR ด้วยมือใช้เวลานาน ตกหล่นหัวข้อกฎหมาย และจัดรูปแบบราชการยาก ระบบนี้บังคับโครงสร้าง 13 ส่วน (s1–s13) ตรวจด้วย Rule Engine แล้วส่งออก Word/PDF ตามมาตรฐานราชการ (TH Sarabun New, วันที่ พ.ศ.)

## ผู้ใช้

- **เจ้าหน้าที่ (officer)** — สร้างโครงการด้วยฟอร์ม (ชื่อ หน่วยงาน วงเงิน ประเภท แม่แบบ) แล้วร่าง 5 Phase ส่งตรวจ ส่งออก ตรวจไฟล์ภายนอก
- **ผู้ตรวจสอบ (reviewer)** — ดูโครงการทั้งหมด อนุมัติหรือส่งกลับ
- **ผู้ดูแลระบบ (admin)** — แม่แบบ ฐานความรู้ (จัดการ) ผู้ใช้ และการตั้งค่า AI (Local / Cloud / Hybrid)

## ความสามารถหลัก

1. พื้นที่ทำงาน **5 Phase (0–4)** ที่แมปไปยัง s1–s13 (หมวด 4 มีหัวข้อย่อย 4.1–4.14)
2. อัปโหลดแบบจัดประเภทใน Phase 0 — สกัดข้อความ ตรวจ magic bytes จับคู่ฟิลด์แบบ NLP แล้วให้คนยืนยันก่อนเขียนลงหมวด
3. ร่างด้วย AI: แต่ละหมวดเรียกเอเจนต์ s1–s13 (`get_agent_for_section().draft`) ค่าเริ่มต้น LM Studio + Gemma + EmbeddingGemma-300M หรือคลาวด์เมื่อผู้ดูแลเปิดใช้
4. ตรวจคุณภาพ: กฎหมาย / ความครบถ้วน / ความสอดคล้อง / รูปแบบ / งวดจ่าย / ระยะเวลา (กฎงวดจ่ายและไทม์ไลน์ข้ามเมื่อไม่มีข้อมูล)
5. ส่งออก DOCX + PDF — e-Bidding เป็นงานเจ้าหน้าที่นอกแอป ไม่มีช่องติ๊กปลอมใน Phase 4
6. ตรวจไฟล์ TOR ภายนอกโดยไม่สร้างโครงการ — สกัดแล้วเทียบคู่ด้วย Jaccard (`POST /review/compare-projects` รับ `project_ids` และ `extract_ids`)
7. ฐานความรู้ในเมนูหลัก — RAG จาก `documents/knowledge-base` (extracts, `*_combined.json`, `04-decision-rules`) ไม่ ingest `documents/sources` ในรอบนี้
8. ค่าเริ่มต้นแบบ on-prem — คลาวด์เป็นทางเลือกจากหน้าการตั้งค่า AI และมีผลทันทีหลังกดบันทึก
9. ผู้ดูแลทดสอบการเชื่อมต่อ AI ได้ทันที โดยไม่ต้องรีสตาร์ท
10. ยืนยันหมวด HITL ก่อนส่งอนุมัติ — ปุ่มส่งขออนุมัติกดไม่ได้จนกว่าจะครบ 13 หมวดและยืนยัน HITL
11. ผู้ตรวจสอบ/แอดมินกด **อนุมัติ** หรือ **ส่งกลับ** บนแดชบอร์ดเมื่อโครงการอยู่ในสถานะกำลังดำเนินการ

## ขอบเขตที่ยังไม่ครบในสภาพแวดล้อมนี้

- การ ingest ฐานความรู้เต็มชุดอาจล้มบน Windows หาก bind-mount ชื่อโฟลเดอร์ไทยพัง (Errno 5) หรือชื่อไฟล์ยาวเกิน NAME_MAX ของ Linux — ใช้ `/tmp/kb-linux-seed` + sidecar `.kbname`
- หากเซิร์ฟเวอร์ LLM ในเครื่องไม่ได้เปิด Phase 2 / ร่างด้วย AI จะแสดงข้อผิดพลาดแต่ยังกรอกมือและส่งออกจากข้อความที่กรอกได้
- ไม่มี e-GP จริง, ไม่มี LangGraph checkpointer, ไม่ ingest `documents/sources`
